Architecture Overview

The web runtime is fully separated from heavy computation (document parsing and embedding generation), avoiding synchronous monolithic processing.

📄 Upload .docx→ Django→ Redis Broker→ Celery Worker→ Chunking→ ChromaDB

Ingestion & Vectorization Flow

Document Ingest

A user uploads a .docx file through the Django admin. The record is committed immediately with a pending state.

Task Brokerage

Django dispatches a background task payload to the Redis message broker.

Background Worker Execution

A Celery worker consumes the task, moves the document to processing, and runs the extraction pipeline.

Text Chunking

Raw text is split with RecursiveCharacterTextSplitter using tuned chunk size and overlap to preserve semantic boundaries.

Vector Ingestion

Chunks are embedded into high-dimensional vectors and persisted into ChromaDB.

State Resolution

After successful storage, the document state becomes completed.

Contextual Query Pipeline

The question is converted to a query vector, then ChromaDB returns the top k closest chunks by cosine similarity. These are injected into a deterministic prompt and sent to openai/gpt-oss-120b:free, which is held to strict context-bounding to reduce hallucinations.

Similarity = cos(θ) = (A · B) / (‖A‖ ‖B‖)

Installation & Local Deployment

Prerequisites: Docker Engine and the Docker Compose V2 plugin.

1. Environment Configuration

Create a .env file next to docker-compose.yml with your OpenRouter key:

OPENROUTER_API_KEY=your_actual_openrouter_api_key_here

2. Multi-Container Execution

Launch the web runtime, Celery worker and Redis server together:

docker compose up --build

3. Application Accessibility

  • Django Admin: http://127.0.0.1:8000/admin/
  • Browsable REST API: http://127.0.0.1:8000/api/

Additional Notes

Things worth knowing before you deploy.

  • File Support: Only .docx is supported for ingestion. To add PDF or TXT, extend the extraction pipeline in rag_service.py.
  • Rate Limits: The free OpenRouter model (openai/gpt-oss-120b:free) is rate-limited. For production, consider a paid model and adjust the RAG service configuration.
  • Vector Persistence: ChromaDB persists locally by default. For distributed deployments, use a persistent Docker volume or a cloud-native vector DB such as Pinecone or Weaviate.
  • Task Monitoring: Async tasks are monitored via Celery logs. Integrate django-celery-results or check the QAHistory table for status.
  • Error Handling: Graceful fallbacks for auth faults, network timeouts and rate limits — errors are logged without crashing the worker.
